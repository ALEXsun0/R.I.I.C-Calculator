# 库存副表与有限物品库存

“计算产出”提供赤金、源石碎片、固源岩、装置、龙门币和全部经验值的初始数量。存在库存条件的副表自动启用有限库存，其他排班可手动启用；未启用的旧计算继续使用潜力产出口径。输入仅保存在本地计算设置，不导出到 Mower 排班。

库存从预热开始使用，只由模拟内开工扣料、制造收取、贸易交付改变。进入采样时不重置，不自动补货，不注入关卡、任务或活动收入。每份配方仅开工扣料一次，缺料不部分扣款；制造成品和贸易订单待收取期间不属于仓库库存。结算模式的收益、订单统计和加权评分按实际到账统计，预设数量不计收入；加权评分仍是用户系数下的产出指标，不等于净利润。

条件解释器支持固定来源 Mower alpha `3de2b2ac6f1aeff6513b63faaeea4b2369cf8856` 的六种 `inventory_count` 查询及 `facility_product`。经验按四种作战记录折算后的经验点数输入。实际设施配方优先，无观测时采用原始主表配方；副表预演不改变此观察，支持库存高低阈值与配方共同判断的滞回条件。条件结果改变时唤醒调度，不增加库存专用的固定轮询，不打断进行中的设施操作或受保护的副表换人。

初始数量必须为非负安全整数。非法持久化数据保留供用户修正，并阻断计算，不静默恢复无限库存。底层模拟入口同样强制库存条件使用有限结算，不能通过直接传入潜力模式绕开扣料。综合收益搜索保留预设，不再清零，但原比较器仍不接受有限库存的综合候选评选；本轮不扩展自动生成排班能力。

## 验证范围

合成用例覆盖库存阈值进入退出、实际配方滞回、到账触发、无料停产、未付款订单、开工原子扣料、预热连续性、重复调用隔离、非库存旧行为、UI/Worker 传参及非法保存值。库存扣料中途触发换班的失败用例曾出现约0.62点心情偏差；现在此类条件按实际事件重新积分，不沿用旧班组的预计算终点，手算及两档步长一致。未建房间的配方查询也保留原主表配置。来源是固定源码语义与本地模拟，未执行游戏设备测试。

用户私有原表保留全部副表，使用单独声明的测试库存，在 3 小时预热加 45 小时采样中完成，无外源补货。该复测用于验证库存与原表联动，不代表所有库存组合或原表长期收敛；私有图片、解码排班、库存预算及完整轨迹只保存在被忽略的 artifacts 目录。

回收站只统计材料件数，随机物品身份尚未量化，因此不会为固源岩或装置虚构收入。直接取消已付费制造份仍不退材料，游戏退款规则尚未实测；此边界延续既有切产物模型。菲亚、候补及其他排班策略沿用现有设置。
